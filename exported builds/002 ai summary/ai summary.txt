## 2. What's Been Handled (By Area)

### Cube Engine & Manipulation
- **Integer-state ground truth** — `pieces: Dictionary` keyed by `Vector3i` coords in {-1,0,1}³; logical positions never drift from visuals.
- **Full move set** — 18 face turns (R/L/U/D/F/B + primes + slice M), plus whole-cube rotations (rot_x/y ±).
- **Dual execution paths** — `_apply_move_direct` (instant, "speed-of-light" mode) and `_execute_face_turn`/`_execute_cube_rotation` (tweened, pivot-reparented animation). Both update the same integer registry.
- **FIFO move buffer** — `move_queue` with `_process_queue`, animated vs. instant based on `anim_multiplier`.
- **View-relative notation** — `resolve_wca_notation` maps screen-axis moves to WCA tokens using current `orientation_front`/`orientation_right`/up; supports color-scheme front/right color reporting.
- **Dynamic orientation tracking** — `orientation_front`/`orientation_right` updated on whole-cube rotations.
- **Reset** — `reset_cube()` clears queue, restores orientation, re-spawns pieces, resets clock.
- **Scramble generator** + **notation parser** — paste/generate WCA sequences (ScrambleGenerator, NotationParser).
- **MoveLogger** — per-move WCA token, category, timestamps (elapsed/delta), front/right color context. Clock resettable.

### View & Camera
- **Orbit/free-look camera rig** with yaw/pitch clamping, invert toggles, smooth snap-back on peek release.
- **Camera peek modifiers** (gamepad L3 or MMB) with cooldown to suppress ghost flicks.
- **CubeEnvironment** setup (env/lighting) extracted to its own module.

### Input System (Modular / JSON-Driven)
- **ControllerManager** — scans `res://configs/controls_*.json`, loads default first, cycles profiles (Tab / Guide button).
- **Profile schema** supports button, key, stick, trigger bindings; modifier cube-rotation remapping; camera-peek modifier; stick flick-gating with latch/reset thresholds and deadzone.
- **Keyboard + gamepad + mouse** paths all normalized to `move_requested` signal.
- Joy connection hot-swap handling.

### UI
- **MainHUD (CanvasLayer)** — pause overlay with 4 corner containers, radial vignette shader.
- **Context inspector** — hover/focus-driven description panel (title + body).
- **Mode switcher** — cycles Limitless/Crossle/Baby's First F2L/Custom; updates button label + default description.
- **Module mounting** — `_on_mode_changed` mounts `move_counter` and/or `sequence_deck` per mode metadata (data-driven).
- **Sequence deck** — scramble length slider, optional seed, generate/copy/paste/clear/apply; apply routes through NotationParser → queue_sequence.
- **Speed multiplier slider** (0–5x) → `anim_multiplier` (0 = instant flush).
- **Invert-Y toggle**, **fullscreen toggle**, **quit**.
- **Gamepad navigation** in pause menu (A accept, B close, focus grab).
- **DialogManager**, **DebugUI**, **ControllerOverlay**, **AudioFeedback** scripts present (stubs/early).

### Architecture / Modularity
- Clean separation: **Input (ControllerManager) → Logic (CubeRoot) → Move Tape (MoveLogger) → Visuals (Piece/CubeSpawner)**.
- **ModeManager** as signal-based mode authority; HUD reacts to `mode_changed`.
- **CubeSpawner**, **NotationParser**, **ScrambleGenerator**, **CubeEnvironment** extracted as helpers.
- Signals decouple input from cube execution (`move_requested`, `camera_peek_*`, `profile_changed`, `mode_changed`).
- Data-driven control profiles (JSON) — swappable without code changes.

## 3. Approach Modifications (vs. Original Design)

- **Move execution got a "speed-of-light" fast path.** Original design implied tweened-only pipeline; added `apply_sequence_instant` + `anim_multiplier <= 0.0001` flush so scrambles/training can be applied in one frame. Helps NotationParser/Scramble flows and any future solver playback.
- **View-relative notation instead of fixed WCA axes.** Moves are resolved against current orientation, so logged notation reflects what the player sees; enables front/right color context in MoveLogger.
- **Camera peek introduced as a modifier layer** rather than a separate mode — shares cooldown/gating with stick flicks to avoid ghost triggers. Helps input reliability.
- **HUD built programmatically** (not scene-authored) — containers cleared and rebuilt per mode; trades editor visibility for runtime flexibility/modularity.
- **Move counter module is UI-only so far** — not yet wired to MoveLogger/timer (Phase 4 gap).

---

## 4. Integrity of the Modular System

**Strengths**
- Single source of truth for state (pieces dict + orientation vectors).
- Signal-based boundaries; components don't reach into each other's internals.
- Helpers are stateless-ish (spawner, parser, scramble gen) and reusable.
- JSON control profiles + data-driven mode modules make extension cheap.

**Risks / Coupling**
- `CubeRoot` is a "god spine" — owns camera, pause, queue, orientation, notation, animation. Extensible but centralizes a lot; a second cube instance would duplicate.
- `MainHUD` holds direct refs to `cube_root`/`controller_manager`/`mode_manager` and rebuilds UI in code — flexible but harder to inspect/edit in editor.
- No autoloads registered (per project info) — dependency wiring relies on node paths/exports; fine for single scene, fragile if scenes multiply.
- No unit tests present; verification is manual/run_scene.

## 6. Gaps vs. a Prototype Sandbox (What's Lacking)

- **No undo/redo or time-scrubber** — MoveLogger records but doesn't restore state (Pillar 2 unimplemented).
- **No session state machine** — no IDLE→SCRAMBLE→INSPECTION(15s)→SOLVE(stopwatch)→COMPLETED.
- **Move counter not functional** — UI present, no counting/timer logic.
- **No piece masking** for Crossle (dim/hide non-cross pieces) and no efficiency-vs-optimal comparison.
- **No algorithm library (algorithms.json)** for CFOP triggers/playback.
- **No base_mode hook** / win-condition checking interface.
- **No audio playback wired** — AudioFeedback exists but no SFX assets/events.
- **No solver/optimal-path module** (solver/ empty).
- **No persistence** of best times, profiles in user:// (custom JSON not auto-generated per spec).
- **No tests**; verification manual.
- **Single scene composition** — no main menu, level select, or sandbox scene switching.

Bottom line: the **core manipulation engine and input/UI scaffolding are solid and modular**; the **training, session, audio, and reversibility layers are the main gaps** before it becomes a full sandbox.
